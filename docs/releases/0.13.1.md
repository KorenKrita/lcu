# LCU 0.13.1

**Fixes LCU in Claude Code agent-team teammates, and gives Junie on macOS the instructions on its first prompt.**

## Changes

- **Claude Code agent-team teammates.** A teammate in the tmux or iTerm2 backend is a separate Claude Code process whose turns start from its inbox, so its hooks carry no prompt id, and every `js` and `js_reset` call failed with "Missing exact Claude PreToolUse identity". The relay now uses a turn id of its own for such a turn, replaced when the teammate's `Stop` or `Interrupt` ends it, so Computer Use still ends with the turn by default. Session and tool-use ids are still required exactly. Verified with a tmux teammate on macOS with Claude Code 2.1.310: its hooks had no prompt id and it sent `Stop` after each inbox turn ([#62](https://github.com/amontlabs/lcu/pull/62), thanks @hangox for the fix).
- **Junie on macOS: instructions on the first prompt.** Junie CLI 26.10.20 on macOS starts LCU's relay only after a session's first prompt hook, so a headless `junie --task` run never got the original instructions and an interactive session got them only on its second prompt. A session's first call result now carries them once, before the result. On Linux, where the relay starts early, they still come with the prompt. `lcu setup --agent junie --approval ask` also removes the containers LCU's rules leave empty in `~/.junie/allowlist.json`, and the file itself when nothing else is left ([#61](https://github.com/amontlabs/lcu/pull/61)).

## Upgrading

Run `lcu update`, then restart your agents. To go back, reinstall 0.13.0.
