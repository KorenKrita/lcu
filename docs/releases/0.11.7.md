# LCU 0.11.7

**Fixes Computer use approvals that never reached LCU in the Claude app.** In the Claude app's Code tab, answering the "Computer use" question card for a new app could leave the `js` call waiting until Claude Code gave up (about 30 minutes), most often in auto permission mode.

## Changes

- **The approval card's answer reaches LCU.** The `lcu-approve` mod (0.5.1) sent the person's choice from a timer. Claude Code doesn't run a mod's own permission check on such calls, so the session's permission rules decided it, and auto mode refused it. The mod now asks and records the choice inside its approval hook. The narrow-terminal question dialog had the same problem and is fixed the same way ([1f2ae88](https://github.com/amontlabs/lcu/commit/1f2ae88)).
- **A stuck approval no longer blocks later calls.** If a `js` call ended (for example after `js_reset` or a host timeout) while its approval was still waiting, the Claude Code relay kept that approval open. Later calls' time limits stopped counting, and the Stop cleanup timed out after 120 s. The relay now releases a call's approvals when the call ends.
- **Refused approval calls are logged.** The diagnostic log records `approval_refused` with the reason when the relay refuses an `approval_request` or `approval_choice` call.

## Behaviour changes to know about

- None beyond the fixes. The Claude app's question-card path is covered by Claude Code 2.1.299 run the way the app runs it, not by driving the app itself.

## Upgrading

Run `lcu update`, then restart your agents; it also refreshes the `lcu-approve` mod (a project-scoped mod needs `lcu setup --scope project` again). Your agent registrations and saved choices carry over. To go back, reinstall 0.11.6.
