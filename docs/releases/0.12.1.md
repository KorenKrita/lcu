# LCU 0.12.1

**Update notices now go to you, not to the agent's model.**

## Changes

- **Update notices are shown to the person only.** LCU used to tell the agent about a newer release, with instructions to offer `lcu update`, which read as prompt injection. The notice is now plain information that never enters the model's context: Codex shows it as a hook warning (`systemMessage`), the Claude app shows a toast from the `lcu-approve` mod (now 0.6.0), and Pi and Oh My Pi show a notification when an interactive session starts. Hermes and DeepSeek Harness still show it in `lcu status`, `lcu doctor` and `lcu update --check`. The once-a-day limit and `LCU_NO_UPDATE_CHECK=1` are unchanged. The Codex warning and the Pi notification have not yet been observed in a live session ([#44](https://github.com/amontlabs/lcu/issues/44), [#56](https://github.com/amontlabs/lcu/pull/56), thanks @Suzukaa-a for the report).

## Behaviour changes to know about

- Agents no longer mention LCU updates on their own. Look for the toast, warning or notification instead, or run `lcu status`.
- Codex users keep the update-notice hooks they already have; their output changes with this release, so setup doesn't need to be rerun.

## Upgrading

Run `lcu update`, then restart your agents. `lcu update` refreshes the Claude Code `lcu-approve` mod if LCU installed it. To go back, reinstall 0.12.0.
